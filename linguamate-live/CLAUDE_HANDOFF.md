# LinguaMate Live → Desktop 交接说明

## 1. 用户、目标与当前决策

用户是一名准 AI 产品经理，希望把 LinguaMate 做成 Windows 本地常驻工具，而非继续作为需要手动打开的网页。

目标第一版不是完整 Windows 输入法。它是一个类似输入法体验的桌面悬浮助手：

1. 用户打开软件后，软件在 Windows 托盘常驻。
2. 用户按全局快捷键开始说中文；第一版可以采用“按一下开始、再按一下停止”，快捷键必须可配置。
3. 软件显示小型悬浮窗，上下两行：
   - 第一行：中文净化稿 + 复制按钮。
   - 第二行：英文翻译 + 朗读按钮 + 复制按钮。
4. 英文朗读用于听力和口语学习。
5. 原始 ASR 转写不在 UI 中显示；用户只看到可编辑的中文净化稿和英文。

不要在第一版实现：完整 Windows IME/TSF 输入法、自动向当前应用模拟粘贴、完全离线 ASR/翻译、账号体系、云端历史记录或跟读评分。

## 4.1 Claude 可修改、应修改与不能随意修改的边界

### 可以修改 / 建议修改

1. 新建独立桌面端工程；不要把桌面端脚手架硬塞进现有网页 MVP。
2. 将 `backend/src/server.js` 做**行为等价**的模块化重构，例如导出 `createServer` / `startServer`，以便网页模式和 Electron main process 复用同一套服务。
3. 新建 Electron 主进程、preload、renderer 和桌面悬浮窗 UI。
4. 增加托盘、单实例锁、可配置全局快捷键、复制和英文朗读。
5. 优化净化/翻译提示词，但每次都要用真实中文样例回归验证，重点检查“主语、对象、PPT/产品名、数字”是否被漏译。
6. 添加自动化测试、端到端手动验收清单、无密钥的开发文档。

### 不要随意改动（改动前先理解并测试）

1. **不要删除或重写已验证的腾讯 ASR 签名流程。**
   - `createTencentAsrUrl()` 的参数排序、HMAC-SHA1 签名源串、`/asr/v2/{APP_ID}` 路径、`voice_format=1` 已排过错。
   - 修改后必须用真实腾讯云账号验证，不能只凭单元测试判断成功。
2. **不要改变音频协议，除非同时更新腾讯云对接。**
   - 浏览器端当前发送 16kHz、16bit、单声道 PCM。
   - 每帧为 1280 bytes（约 40ms）；结束时发送 `{ "type": "end" }`。
3. **不要把任何云端密钥暴露给网页、Electron renderer、日志、Git 或安装包。**
   - renderer 只能调用白名单 IPC 或本地后端；密钥只留在主进程/后端环境变量。
4. **不要把原始 ASR 文本重新显示在用户 UI。**
   - 用户已经明确要求只显示中文净化稿与英文。
5. **不要将翻译专用模型用作中文净化模型。**
   - 翻译与净化职责必须分开；`CLEANUP_MODEL` 必须是通用对话模型。
6. **不要为了“净化”而编造或擅自纠正 ASR 事实。**
   - 可删除独立口头词、重复、空占位；人名、数字、产品名、否定词和不确定内容应保留。
7. **不要直接实现自动粘贴、系统 Hook 或开机自启。**
   - 它们是后续明确范围，需单独说明权限、风险与用户开关。
8. **不要破坏现有 `npm start` 网页启动方式。**
   - 桌面版完成前，网页 MVP 仍应可以独立启动并供用户回归测试。

## 5. 已知事实与限制

### 5.1 缺陷记录

#### BADCASE-001 划词弹窗误触发后卡在「正在读取…」且关不掉

| | |
| --- | --- |
| 报告日期 | 2026-10-18 |
| 报告人 | 用户 |
| 复现条件 | 未按 `Ctrl+C`，划词弹窗自行出现，停在「正在读取…」，点 `[×]` 无反应 |
| 严重度 | 高——弹窗盖住正在输入的内容且无法关闭，用户只能重启应用 |
| 根因 | **两个独立缺陷叠加**，均已用代码与测试定位 |

**缺陷 A：并发触发会产生「孤儿窗口」，它既收不到更新也关不掉。**

`showTranslationPopup` 在 `await readForeground()`（一次 PowerShell 调用，约 300ms）**之前**
调用 `destroy()`。两次触发并发时（语音输入法一轮写两次剪贴板，两次间隔约 500ms，正好落进
划词的可触发区间 `[280ms, 1000ms]`），两次调用会先后都通过 `destroy()`，再各自建一个窗口，
后一个把 `win` 的引用覆盖掉。

被覆盖的那个窗口**仍然留在屏幕上**，但：

- `update()` 只发给 `win`，所以它永远停在建窗时的初始文案「正在读取…」；
- `isOwnSender()` 会拒掉它发来的 `popup:close`（sender 不是当前 `win`），所以 `[×]` 与 Esc 都被忽略。

两者叠加的表现就是截图里的样子：**一块冻在「正在读取…」、点 × 没反应的面板。**

复现测试：`test/popup-manager.test.js` 的「单例：并发触发（不等前一次建完）也只留最新一个」。
现有那个「连续触发只留最新一个」的测试是**顺序 `await`** 的，两次调用不会交错，因此抓不到这个缺陷。

**缺陷 B：压制分支留下了没人收的骨架弹窗。**

`handleSelectionUnreadable` 在 `LINGUAMATE_UNREADABLE_COOLDOWN_MS`（默认 30s）压制期内直接
`return`，但 `onCaptureStart` 已经先建好了一个「正在读取…」骨架。全文件只有截图路径和退出时
`dispose()` 会调 `popupManager.close()`，**压制路径不关它**。

结果：**每一次被压制的触发都会在屏幕上留下一块永久停留在「正在读取…」的面板**，
直到下一次触发把它顶掉或应用退出。压制的本意是「别打扰用户」，留下空壳恰恰是最打扰的一种。

**与 2026-10-04 右 Alt 误触发的关系**：同源。缺陷 A、B 都是那次修复（加重复压制）没有覆盖到的
路径——当时只处理了「最终那块『无法读取』面板」，没处理「骨架面板」和「并发建窗」。

**修复（2026-10-18 已完成）**：

1. `showTranslationPopup` 的 `destroy()` 移到 `await readForeground()` **之后**，并加 `showSeq`
   序号：await 期间若又来一次触发，序号对不上，本次直接放弃返回 `null`。同时用 `Set` 记录
   **所有**活着的窗口，`destroy()` 遍历关闭——结构上杜绝孤儿，兜底也不留死角。
2. 压制分支 `return` 之前先 `popupManager.close()` 收掉骨架。
3. 新增 `CAPTURE_WATCHDOG_MS = 8000` 看门狗：判定为双复制后 8 秒内既没读到内容、也没走到
   「读不到」，就收掉骨架。任何将来新加的分支忘了收尾，也不会再留死面板在屏幕上。
   `handleSelectionCaptured` / `handleSelectionUnreadable` 进入时清除，`will-quit` 也清除。
4. `loadFile` 的失败改为 `catch` 返回 `null`（原先会一路冒成没人接的 rejection）。

回归测试：`test/popup-manager.test.js` 新增两条——「并发触发也只留最新一个」（修复前红：
`实际有 2 个`）与「孤儿窗口若存在，[×] 与 Esc 都必须还能把它关掉」。修复后 **139/139 通过**。

**注意**：用户当时运行的是 `D:\安装\linguaMate\LinguaMate.exe`（2026-10-11 打包，含 10-04 的
全部修复、不含本次修复）。修复要生效**必须重新打包安装**。

#### BADCASE-002 划词误触发时仍会弹出「无法读取」面板（2026-10-20）

在 BADCASE-001 之后加的**骨架门控**，效果与它的边界必须一起记下来，否则下一个人会
误以为「误触发已经彻底消失」。

**改了什么**：`selection-capture.js` 的 `handleTrigger()` 从「先建骨架、再去读」改成
「**先读，确认真的拿到了纯文本才建骨架**」。`main.js` 里 `onCaptureStart` 的调用时机
随之从「判定为双复制的瞬间」挪到「内容已在手」。

**为什么**：位图写入会把剪贴板的纯文本格式一起清掉（实测 `textlen=0`），所以语音输入法
那一轮写入之后 `readText()` 必然为空。既然必然为空，就没有任何理由先在屏幕上摆一块
「正在读取…」——先出声再撤回，哪怕撤得掉也是一次闪烁，撤不掉就是 BADCASE-001 的死面板。

**实测结果（冷却设为 0、压制全开的条件下跑 8 次位图触发）**：

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| `start`（建骨架） | 8 | **0** |
| `start-watchdog` | 可能 1 | **0** |
| `captured`（误翻译） | 0 | **0** |
| `unreadable` | 8 | 8 |

**边界——必须如实说**：改后输入法触发**仍然会弹一块面板**，只是从「正在读取…」换成了
「无法读取」。走 `onUnreadable` 那条路，而 `handleSelectionUnreadable` 不受门控影响。
默认 30s 冷却意味着实际体验是「每 30 秒弹一次」，不是「彻底安静」。

要彻底静默就得让 `onUnreadable` 在 `reason === 'no-plain-text'` 时直接 return，代价是
**复制图片后双击 Ctrl+C 也不再有任何提示**，用户失去了「[截图翻译]」这个出口
（托盘菜单与 `Ctrl+Shift+S` 仍在）。这一步**尚未做**，等用户拍板。

**顺带修掉的一个隐患**：`handleSelectionUnreadable` 的压制分支里那句
`popupManager.close()` 必须删掉。它当初是缺陷 B 的补丁，但门控之后走到 unreadable
说明**一次骨架都没建过**——屏幕上那块面板属于别的操作（很可能是用户刚做完的截图翻译），
替它 close() 等于「输入法每敲一次就关掉用户的截图译文」。缺陷 B 现在是被结构性消除的
（骨架压根不会被创建），不再需要事后收尾。

**已修的既有损坏**：`test/selection-capture.test.js` 里有一处 U+FFFD 替换字符
（「第一〔U+FFFD〕自报选区」，原文应为「第一个」），来自更早某次编辑。已修复，并全仓扫过，
跟踪文件里不再有替换字符。**注意：写文档时不要为了展示这个损坏而把它重新打出来。**

### 5.2 事实与限制

- 这是“本地运行但使用云端 AI API”的产品，并非完全离线：音频会送到腾讯 ASR，文本会送到 TokenHub 模型。
- ASR 的错词不能由净化模型随意猜测纠正；净化只能删口头填充、重复和无内容占位。
- 目前自动化测试仅覆盖健康检查与基础语法；语音端到端依赖手动麦克风测试。
- 浏览器现有 UI 的“正在识别/正在整理”只是状态，不显示 ASR 原文。
- 用户很在意：英文翻译不能漏掉“我做的 PPT”等主语或对象。改翻译提示词前后都要用真实中文例句验证。

## 6. 推荐桌面技术方案

首选 Electron，而非 Tauri：现有项目已是 Node + 原生 Web 前端，Electron 复用成本最低。

桌面端已建于同级目录 `D:\zxf\claude\LinguaMate\linguamate-desktop`，现有 `linguamate-live` 网页 MVP 完整保留。

建议组件：

| 能力 | 推荐实现 |
| --- | --- |
| 常驻与托盘 | Electron `Tray` + 单实例锁。 |
| 全局快捷键 | Electron `globalShortcut`；先实现“按一次开始、再按一次停止”。它只提供按下回调，不要假装能可靠监听快捷键松开。按住说话如必须实现，应评估 Windows 原生键盘 Hook/可信原生模块并单独测试打包兼容性。 |
| 悬浮窗口 | 独立 `BrowserWindow`，`frame:false`、`alwaysOnTop:true`、`skipTaskbar:true`，窗口小、可拖动、默认隐藏。 |
| 录音与现有 AI | 在 Electron renderer 中使用麦克风；复用腾讯 ASR → 净化 → 翻译链路。优先将现有后端重构为可由 Electron main process 启停的模块，同时保留 `npm start` 网页开发方式。 |
| 复制 | Electron `clipboard.writeText()`，用受限 IPC 调用。 |
| 英文朗读 | 首版用 renderer 的 `speechSynthesis`，选择英文系统语音；支持“播放/停止”即可。 |
| 本机配置 | 开发阶段 `.env`；面向他人发行时不要将云端密钥打入安装包，应迁移到用户自己的后端或安全凭据存储。 |
| 打包 | `electron-builder` 输出 Windows 安装包，测试安装、卸载、托盘、麦克风权限与杀毒软件提示。 |

Electron 安全要求：本地 HTML 资源；`nodeIntegration: false`；`contextIsolation: true`；只用 `preload` + `contextBridge` 暴露极小的白名单 IPC；不要把任意 IPC 直接透传给 renderer。

## 7. 建议实施顺序

1. 初始化独立 Electron 工程，能启动托盘和一个隐藏/显示的悬浮窗口。
2. 实现可配置的全局快捷键；若快捷键被系统占用，向用户明确显示失败原因。
3. 将现有 `backend/src/server.js` 重构成可复用的 `createServer`/`startServer`，让网页模式与桌面模式共用，不要复制两套 ASR 签名或模型调用逻辑。
4. 悬浮窗只实现两行结果：中文净化稿 `[复制]`；英文 `[朗读] [复制]`。保留编辑能力。
5. 先做“按一次开始、再按一次停止”；获得用户确认后再处理“按住说话、松开结束”的 Windows 键盘 Hook。

## 8. 验收标准

- 软件不需要用户打开 Chrome。
- 软件打开后在托盘可见；退出菜单可安全关闭所有服务。
- 全局快捷键能显示悬浮窗并开始录音；再次按下可结束录音。
- 窗口只显示中文净化稿和英文，不显示原始文本。
- 中文和英文均有复制按钮；英文有播放/停止朗读按钮。
- 连续语句不会因上一句翻译较慢而阻塞下一句的后台处理，最终显示顺序仍正确。
- 密钥不出现在 UI、日志、安装包源码或 Git 中。
